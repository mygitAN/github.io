Multi-agent reinforcement learning, action design

From blended weights to discrete choices

A portfolio agent that outputs blended weights can always hedge, so a single agent and a multi-agent (MARL) system end up giving the same kind of answer. Here each one picks from a fixed list instead, and equal weight, the single agent and MARL are then compared on equal terms. The pictures below show that change, and why the continuous TD3 algorithm makes way for a discrete one.

How to read the pictures

Every picture stands on the same triangle. Each corner is one sleeve held at 100%. Any point inside the triangle is a blend, and the centre is equal weight. Height shows a number the agent cares about: a probability in part 1, a value estimate in part 2. Drag any picture to turn it.

Discrete choices

MARL, a fixed menu of splits

An example menu: the three single sleeves, equal weight, three 50/25/25 tilts, and a Hold option that keeps the current split. The menu contains every single-agent choice and equal weight, so MARL can in principle do at least as well as both.

Switch the selection rule and watch the counters. When the agent always takes the top option, the choice changes only when the ranking changes. When it samples from the SoftMax, the choice can jump while the scores barely move, so the switch count climbs. That extra trading has to be measured under the same costs and data.

Part 2

Continuous TD3 compared with a discrete algorithm

Both pictures read the same value estimate. TD3 treats it as a smooth surface and feels for the slope. A discrete algorithm reads it at the menu points only and compares the heights.

Value estimate
Continuous, TD3

One point, moved by the slope

The critic gives a value for every possible blend. The actor holds one point and moves it uphill using only the slope under its feet. The wire mesh is the second critic. TD3 trusts the lower of the two when it builds its learning target.

Discrete, DQN style

Score every option, take the tallest

The network gives one value per menu option. There is no actor and no slope. It compares the pillars and takes the tallest, or passes them through a SoftMax and samples.

Now choose the nearly flat estimate, which is the likely situation with a few hundred monthly transitions. The TD3 actor has almost no slope to follow, so it slides to an edge and sticks there. That is the saturation problem. The discrete agent still ranks its options, but when the pillars are almost the same height the ranking flips with noise.

So discrete actions remove the hedging and the reliance on slope. They do not make a noisy value estimate accurate, which is why a careful statistical comparison matters more than the algorithm swap.
